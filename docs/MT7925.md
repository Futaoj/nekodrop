# MediaTek MT7925 / AMD RZ717 (`mtkradio`) — Experimental User-Mode Notes

Status: **experimental, On-Demand mode only**, awaiting real-hardware verification across end-to-end nekodrop runs and Windows reboots. If anything goes wrong, Start menu → **nekodrop - restore Windows Wi-Fi** hands the card straight back to the MediaTek / AMD vendor driver; please attach a diagnostic report in a GitHub Issue either way.

## Architecture & Pure User-Mode Integration

MT7925 (Connac3, Wi-Fi 7) is driven by `nekodrop-radio-mtk.exe` (`mtkradio/`) over nekodrop's standard on-PC self-signed UMDF register proxy (`driver/regproxy/winawdl_regproxy.inf`, `WUDFRd`, UMDF 2.31) — the same architecture used by Intel, Realtek, and MediaTek MT7902/MT7921/MT7922 cards:

- **No kernel driver, no test signing, no disabling Secure Boot**: relies solely on `winawdl_regproxy` (`WUDFRd`) and user-mode 32-bit DMA pages (`AllocateUserPhysicalPages` via `SeLockMemoryPrivilege`, granted to `NekoDropService` under `LocalSystem`).
- **Standard generic INF binding**: binds `PCI\VEN_14C3&DEV_7925` under the standard `RegProxy` section (no `SUBSYS` lock, ranks below the vendor driver so installing nekodrop never takes the card on its own).
- **On-Demand mode (`SupportsConcurrentWifi = false`)**: Windows keeps the vendor Wi-Fi driver at boot and while idle; nekodrop takes the card only during AirDrop transfers and returns it automatically when idle or on service shutdown.

## Channels & Regulatory / TX Power

- **Dual-band AWDL support**: channel 6 (2.4 GHz, 20 MHz) and channels 44 / 149 (5 GHz, 80 MHz).
- **Conservative TX power & firmware regdomain / CLC**: regulatory limits and TX power are configured directly in user mode using conservative TX power limits and the firmware's regdomain / CLC tables — no kernel SAR filter driver or test signing is required.

## How to Test & Report

1. **Quick hardware probe & firmware boot check** (after binding `winawdl_regproxy` from an elevated prompt, or inside a staged build):
   ```powershell
   .\radio\nekodrop-radio-mtk.exe --probe
   .\radio\nekodrop-radio-mtk.exe --boot-test
   ```
2. **End-to-end AirDrop test**: run nekodrop in On-Demand mode, test discovery and bidirectional transfers with an iPhone/iPad/Mac, and verify the card returns cleanly to Windows Wi-Fi afterwards and across a reboot.
3. **Send a diagnostic report**: run Start menu → **nekodrop - diagnostic report** (or `powershell -ExecutionPolicy Bypass -File installer\report.ps1`) and attach the redacted `.md` report and `.txt` log in a [GitHub Issue](../../../issues).
